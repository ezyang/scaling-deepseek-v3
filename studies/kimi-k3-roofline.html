[[AI: The question: with a fixed global batch, GB300 NVL72 hardware and a fixed mixed-precision recipe, what is the smallest cluster that trains Kimi K3 at (close to) its best tokens/s per GPU? Part 3’s method, run again: count the FLOPs, count the bytes each parallelism moves per link, divide by the link’s rate, and check that compute covers the communication. Everything here is a speed-of-light number: spec peaks, perfect overlap, no kernel inefficiency. The sheets are live, as in part 3: the formula column is the program, blue values are knobs, and every sheet’s header downloads the whole page as one workbook.]]

[[AI: Assumptions carried from the brief: forced-balanced routing (every EP rank receives exactly S · k tokens per sequence, as MoonEP guarantees); a rank-aware pipeline cache for the attention residual, so each layer output crosses a pipeline boundary once; cross-rank activation offload, so the in-flight activations of 1F1B are averaged across pipeline ranks; and two activation-checkpointing policies, A (recompute everything that is not a matmul) and B (recompute everything except SDPA, KDA and the routed experts).]]

[[AI: Reading the tables: tokens/s per GPU falls monotonically with cluster size once the model fits, because the per-step fixed costs (ZeRO-1 traffic, the bubble) amortize over fewer tokens per GPU, and the layout that wins at every size is one replica of a PP × EP grid that just fits. So “the minimum number of GB300s that maximizes tokens/s per GPU” is the smallest cluster at which the preferred policy fits: with FP32 gradients and states, four domains (288 GPUs) under policy A, three (216) under policy B at a 13 % lower rate; BF16 optimizer states buy policy A the three-domain cluster, and BF16 gradients as well take policy B down to two. Fits above 95 % of device memory should be read as “on the line”: this roofline holds no communication buffers, no fragmentation, no vision tower. Not modeled: virtual pipeline stages, context parallelism, MoonEP’s redundant experts, the vision tower, MTP, activation offload bandwidth, and any kernel efficiency below the spec peak (set η).]]
